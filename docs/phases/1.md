# Phase 1: `sy` on one machine

From plan section 16. Branch `phase-1`, tag `v0.1`. No hub yet: everything goes to the local
outbox and is read back locally. Needs phase 0.

The prototype keeps running unchanged during this phase. Its hook (`~/.claude/switchyard-hook.sh`)
and `sy hook` both run on each event; that is fine because they write to different places.

## Tasks

### Foundations

- [x] **`internal/paths`** (paths.md): the three folders per OS, XDG rules, `SY_*_DIR` and
  `SY_HOME` overrides, never `SWITCHYARD_DATA`. `sy paths` prints them with their source.
  - Accept: table-driven tests per OS (with `GOOS` build tags or injected env/home), and a
    test that `sy` never writes anything into `~/.config/switchyard` except `config.toml`.
- [x] **`internal/config`**: read/write `config.toml`, unknown keys kept, atomic write.
  Choose the TOML library (candidate `github.com/pelletier/go-toml/v2`) and record why here.
  - Accept: round-trip test keeps comments-free unknown keys; `sy config get/set`.
  - Done. TOML library: `github.com/pelletier/go-toml/v2` v2.4.3. Why: pure Go, no cgo
    (the binary stays a single static file on all OSes); TOML 1.0 complete; decodes to
    `map[string]any`, which is how unknown keys survive a rewrite (the typed `Config` is a
    read-only view); actively maintained and widely used; one small dependency. Rejected:
    BurntSushi/toml (also fine, but its `MetaData.Undecoded` route needs a second pass to
    keep unknown keys) and a hand-written parser (not worth the bugs). Cost: it does not
    keep comments, so `Save` writes a two-line header and hand-written comments are
    lost; `sy config set` is the supported way to edit (paths.md section 4 allows this).
    `sy config get|set` knows the keys of paths.md section 4 (`slots.labels.<slot>` is
    free-form); `set` refuses unknown keys but never removes unknown keys already in the file.
  - Also added `internal/atomicfile` (temp + fsync + rename + dir fsync), shared by config
    and identity.
- [x] **`internal/record`**: envelope and the seven kinds with raw overflow (record.md),
  ULID ids (`crypto/rand`), the content rules of record.md 4.1 and the key filter of rule 4.
  - Accept: the phase 0 round-trip test passes; a test per content field shows it is
    removed and `redacted` lists it; `iguana_necktie` and an injected unknown key survive.
- [x] **`internal/outbox`** (outbox.md): append with the day-file lock, torn-line repair,
  spill files, fsync, readers that stop at the last newline, `sy outbox append` for other
  writers.
  - Accept: a test starts 50 processes (re-exec of the test binary) appending 200 records
    each, mixed sizes up to 256 KiB: every line parses, no record is lost or duplicated.
    A torn-line test (truncate mid-line, append again) loses only the torn record.
    Benchmark: append p95 under 5 ms on the laptop SSD.
    Measured 2026-10-12 (`go test -bench Append ./internal/outbox`, fsync on): tmpfs p95
    0.16 ms; btrfs NVMe under a load average of about 90, p50 6.5 ms and p95 27 ms, so the
    budget is **not yet shown on btrfs**: re-measure on an idle machine, and decide whether
    `fdatasync` on btrfs needs `outbox.fsync = false` or a sync done after `sy hook` replies.
- [x] **`internal/identity`** (identity.md): machine id creation under lock, slot discovery,

### Notes on `sy hook`, `sy statusline` and the plugin (as built)

- `sy hook`: identity comes from the cached login only. If the cache is missing, older than
  12 h, has no seat (older than 10 min), or a SessionStart finds it older than 1 h, a detached
  `sy hook --refresh-auth` runs `claude auth status --json` (debounced to once per 10
  minutes by `<state>/identity/refresh-auth-<slot>.stamp`, one per slot). `sy flush` is started after every hook,
  at most once a second (`<state>/flush.stamp`), and is a no-op until phase 2. Errors:
  one line in `<state>/hook-errors.log` (reset at 64 KiB); exit 0 and no output always.
  `derived.hook_ms` is the time from process entry to just before the outbox write.
  Latency of the whole process (build once, 100 runs, test machine under load):
  p50 about 5 ms, p95 about 10 ms (`cmd/sy` `TestHookBinaryLatency` logs it).
- `term.focus_url` prefers `LC_SY_FOCUS` over `WARP_FOCUS_URL`; `term.host` is not set by the
  hook (it cannot know the laptop's machine id).
- `sy statusline`: prints `<wrapped output> │ <label> · 5h 24% · 7d 41% · ctx 9%` on one
  line (dim ANSI for ours; absent values are left out). The wrapped output is unchanged except
  that its final newline is dropped so ours continues the line. Wrapped command: `sh -c`
  (`cmd /c` on Windows), same stdin, 2 s limit (timeout or failure to start prints only
  ours; a non-zero exit keeps what it printed). Label: `slots.labels[<slot>]`, else the
  folder name without the leading dot. Samples: `<state>/statusline/last.json`; first run of a
  session, then at most once a minute and only when the 5h or 7d value changed.
- Plugin hook commands are `command -v sy >/dev/null 2>&1 && sy hook <Event> || true`.
  `claude plugin validate plugin/switchyard --strict` passes.
- End-to-end test (`SY_E2E_CLAUDE=1 go test ./cmd/sy -run E2E -v`): real `claude -p` with
  `--plugin-dir`, temp `SY_HOME`, built `sy` first on PATH; checks SessionStart,
  UserPromptSubmit, Stop and SessionEnd records with the right machine, slot and seat.
