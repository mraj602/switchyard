# Phase 2: Hub and web board

From plan section 16. Branch `phase-2`, tag `v0.2`. Needs phase 1.

## Tasks

### Hub core

- [x] **`internal/hub/store`**: open SQLite with modernc.org/sqlite (WAL, `busy_timeout`,
  `foreign_keys = ON`, one writer connection plus a read pool); embed migrations; v1 =
  `docs/spec/schema.sql`. Copy the file before migrating (plan section 7).
  - Accept: a test checks the embedded v1 migration equals `docs/spec/schema.sql`, and that
    migrating an empty database gives the same `sqlite_schema` as loading the spec.
  - Done: writes go through one connection (`_txlock=immediate`) behind a mutex, reads use a
    `query_only` pool. **Spec change: schema v2** (`0002_session_transition.sql`) adds
    `session_transition` so `/v1/sessions/{id}` can show the state history;
    `docs/spec/schema.sql` is now v2 and the test compares against the latest migration.
    Migrating an existing database first writes `<db>.pre-v<N>-<time>.bak` (`VACUUM INTO`).
- [x] **`sy hub serve`**: HTTP server on `127.0.0.1:8787` by default (`--listen`), graceful
  shutdown, `/health`. Refuses a non-loopback listen address without TLS in front unless
  `--insecure-lan`.
  - Done: `--listen` (alias `--addr`), `--db`, `--quiet`; one log line per request with
    the path only (never the query, so `?token=` stays out of logs); SIGINT/SIGTERM drain
    for up to 15 s and end open streams.
- [x] **`internal/hub/auth`** + `sy hub token create|list|revoke` (tokens.md): token
  format, SHA-256 lookup, scopes, `last_used_at` at most once a minute.
  - Accept: tests for each scope against each endpoint's `x-scopes` in `api.yaml`
    (generated table), revoked tokens get 401 immediately.
  - Done: the route test reads every operation and its `x-scopes` from `api.yaml` and
    checks the router agrees. Machine and desktop tokens need `--machine`. Failed logins
    are limited to 10 a minute. **Spec fix:** tokens are 48 characters, not 49
    (`sy_` + kind + `_` + 43); tokens.md said 49.
  - Board login: `POST /v1/session/login` makes a separate **read-only** `browser` device
    (`created_by login:<parent>`) whose token is the `sy_session` cookie, so a cookie never
    carries write or push scope even when a desktop token was used to log in. Revoking the
    parent revokes its board sessions.

### Ingest and folds

- [x] **`POST /v1/ingest`** (`internal/hub/ingest`): gzip, size limits, per-record
  validation (record.md 5), `INSERT … ON CONFLICT(id) DO NOTHING` into `record`, duplicate
  and `id_conflict` detection, reply listing every id. Then type each new record in the same
  transaction: machine/slot/seat/slot_login (identity.md 5), session, hook_event,
  token_row (max-merge), limit_sample, web_usage, history_day.
  - Accept: sending the same batch twice changes nothing and both replies list all ids as
    accepted; a record with an unknown kind is stored with `typed = 0`; a web usage body
    keeps `iguana_necktie` and an injected unknown key byte-for-byte in `record.body`.
  - Done: limits 8 MiB per batch, 1000 records, 1 MiB per record. An empty `records` array
    is a 400 (`sy connect` uses it to prove a token). Typing errors are kept in
    `record.type_error` and never reject the record. Tests: idempotency, `id_conflict`,
    per-record rejection, 20 concurrent ingesters, restart mid-stream.
- [x] **State engine** (`internal/hub/state`): the phase 1 fold, persisted to
  `session_state`; late records refold the session; gone detection from session lists
  (states.md 5); `stale` and `machine_stale` at read time.
  - Accept: replaying `record` into an empty database gives identical `session_state`.
  - Done: incremental `Apply` per hook/list record; a record older than the session's last
    input refolds the session from `record`. `session_state.updated_at` is the time of the
    newest input folded in (not the wall clock), so a replay gives the same row.
    `hook_event.state_after` and `session_transition` are written with each fold. Tested by
    folding `testdata/hooks/runs` through ingest in order, as one batch and reversed: every
    step matches `internal/hub/state`. Deferred: a `sy hub replay` command (the store has
    `RecordsForReplay`; not wired to a CLI).
- [x] **Usage model** (`internal/hub/usage`): `limit_sample` → `usage_window` (peak, final,
  unused at reset), pace bands; web usage windows from the raw response using the
  prototype's `windowsOf` rules (every `utilization` key, plus model-scoped `limits`).
  - Done: a sample joins an existing window when `resets_at` is within 5 minutes; the
    freshest sample sets `final`, the raw response is kept. Tested against the prototype's
    own `windows` rows.
- [x] **Machine heartbeats**: `machine.last_seen`, `last_record`, `backlog` (sent by
  `sy flush` as a header, `X-Sy-Backlog`, and stored).

### Read API and stream

- [x] **`/v1/overview`, `/v1/sessions`, `/v1/sessions/{id}`, `/v1/accounts`,
  `/v1/accounts/{seat}/windows`, `/v1/machines`** as in `api.yaml`.
  - Accept: response bodies validate against the OpenAPI schemas in a test.
  - Done: `/v1/sessions` filters `state`, `seat`, `machine`, `since`, `days`, needs-you
    first; `/v1/seats` aliases `/v1/accounts`. Reserved paths answer 501 before auth.
    Unknown `/v1/` paths are a JSON 404. The board is served at `/` without auth,
    `Cache-Control: no-cache`. Deferred: validating bodies against the OpenAPI schemas
    (tests check the fields the board uses; `webui/devserver` checks the fixtures).
- [x] **`/v1/stream`** (SSE): `hello`, `reset`, `ping` every 25 s, `session`, `usage`,
  `machine`; `Last-Event-ID` resume from a 10-minute / 5000-event buffer.
  - Accept: a test client sees a `session` event within 100 ms of an ingest that changes
    state.
  - Done: event ids start at the hub's start time in ms × 1000, so they keep rising across
    restarts and an id from an older hub gets `reset` (`hub_restarted`). `?token=` is
    accepted on the stream only. The test allows 2 s (it runs under `-race` in CI); events
    are published right after the ingest commits.

### Getting records to the hub

- [x] **`sy connect <url> --token <token>`** (tokens.md 4): HTTPS check, `/health`, token
  check, writes `<state>/token` (0600) and `hub.url`, one flush, installs the timer.
  `sy disconnect` undoes it. (`internal/client`, `internal/timer`, `cmd/sy/connect.go`.)
  Deferred: one `slot_info` per slot (needs slot discovery from `sy scan`/`sy agents`); the
  token is proven instead with an empty batch (401/403 bad, 400 good), which stores nothing.
  Plain http is allowed for loopback, Tailscale (`*.ts.net`, 100.64.0.0/10, short MagicDNS
  names) and with `--insecure-lan`.
- [x] **`sy flush`** (`internal/client`, outbox.md 5): batches, gzip, cursor, backoff,
  rejected log; started detached by `sy hook` (debounced 2 s).
  Flags: `--quiet` (hook/timer: silent, exit 0, honours stored backoff and a rejected
  token), `--wait`, `--force`, `--timeout`. Run by hand it ignores both. State in
  `flush.status.json` (for `sy doctor`) and `cursor.json` (`failures`, `retry_after`).
  A reply that omits ids advances the cursor only past the answered prefix. A batch the hub
  refuses with 400/413 is halved down to the one record at fault, which goes to
  `rejected.jsonl` (at most 10 per run).
- [~] **`sy tick`** and the OS timer: systemd user timer (every minute) on Linux with a
  `loginctl enable-linger` check, launchd agent on macOS. The timer part is done
  (`internal/timer`, installed by `sy connect`, golden-tested) and runs `sy flush --quiet`;
  `sy tick` itself is not built, switch `timer.Command` to `tick` when it is. Runs flush, then `sy agents`
  every 5 minutes, then `sy scan`.

### Board and deployment

- [x] **Web board** (`webui/`): port the prototype's `web/` to the new API: Now, Sessions,
  Session detail, Accounts, Machines, Login, matching `docs/design/screens/` (read-only;
  desktop sidebar, phone bottom tabs, light and dark). Embedded with `embed.FS` as
  `webui.FS()`. Live via `EventSource` on `/v1/stream` (reconnect with backoff, refetch on
  `reset` or a manual reconnect, polling fallback). Login posts a token to
  `POST /v1/session/login` (added to `api.yaml`); the hub must accept the `sy_session`
  cookie on the read endpoints and the stream. Mock hub: `go run ./cmd/webui-dev`.
  - Accept: `webui` tests check `index.html` and everything it loads is embedded;
    `webui/devserver` tests check the fixtures against `api.yaml`; the headless-browser
    smoke test (`SY_WEBUI_BROWSER=1 go test ./webui/smoke`, see its doc comment) loads every
    page at 1440 and 390 px with no console errors and checks a live update.
  - Deferred: analytics page, account history charts, web push and install manifest
    (phase 4), per-session "focus terminal" (desktop app only).
- [x] **Deploy** (`deploy/`, README with the OCI/Tailscale and merged-mode steps): Dockerfile (static `sy`), compose file for the OCI server
  behind `tailscale serve` (decision 3), data volume. Merged-mode fallback: user service
  with linger.
- [x] **`sy hub backup`** (SQLite online backup, nightly) and **`sy hub prune --before`**.
  - Done: `backup --to <file>` (`VACUUM INTO`, 0600; default `<data>/backups/hub-<UTC>.db`),
    `prune --older-than 90d | --before <date> [--dry-run]`. Prune deletes raw `record` rows
    (and their `hook_event`), `limit_sample`, `web_usage`, `token_row` and `limit_hit`
    older than the cut; it never touches seats, machines, slots, sessions and their
    states, transitions, usage windows or history days. A late record for a session whose
    records were pruned refolds from what is left. Nightly scheduling is left to the
    deployment (cron/systemd timer).
- [~] **Prototype history**: the importer is built (`sy hub import-prototype`, see phase 0)
  and was run on a copy into a scratch hub with matching counts. Still to do: run it against the live hub, then switch off

## Notes

- Ingest is the only writer path from clients. The read API never writes, except
  `last_used_at` on devices.
- Keep the store behind one interface (plan section 7) so Postgres can be added later, but
  do not build that abstraction beyond what the hub needs now.
