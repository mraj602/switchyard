# Phase 6: Desktop app

From plan section 16 (and section 6, decisions 1 and 2). Branch `phase-6`, tag `v0.6`. Needs
phase 2 (hub, board, `/v1/stream`), phase 3 (`sy setup`, the hub user service, `sy account`),
phase 4 (pairing codes, owner links, alerts) and phase 5 (admin channel `machines.hub_admin`).
The desktop app is a new Electron app in a new top-level folder, `app/`. It holds account tabs,
reads web usage and shows the hub. Everything else it used to do is now done by `sy` and the hub.
This file says who builds what, in which files, and how it is proven. The contract itself is
[docs/spec/desktop.md](../spec/desktop.md) (wave 0 moved the **Contract** sections there, so
the spec folder stays the single contract; spec README: a change goes there first).

Screens: `docs/design/screens/DeskHome`, `DeskSessions`, `DeskAccounts`, `DeskAccountTab`,
`DeskAlerts`, `DeskMachines` (`.dc.html`).

## The live prototype is off limits

The user's Electron prototype runs from the repo root every day: `main.js`, `preload.js`,
`core/`, `server/`, `shell/`, `web/`, `bin/`, `assets/`, the root `package.json` and
`package-lock.json`, and the root `test/*.js`. It keeps its data in `~/.config/switchyard`
(Linux), `~/Library/Application Support/switchyard` (macOS) and `%APPDATA%\switchyard`
(Windows). The rules below are hard rules.

1. No agent modifies, moves, renames or deletes any of those files. No agent edits the root
   `package.json` either: no npm workspaces and no new scripts. `app/` has its own
   `package.json` and lockfile.
2. The new app never opens, writes or locks the prototype's user-data folder. The one
   exception is the importer in WP-F, which reads it and copies from it, and only when the
   person asks.
3. The new app does not bind the prototype's hook port (47821). It writes no autostart or
   launcher entry under the prototype's names (`switchyard.desktop`), and it registers no
   login item that would replace the prototype's.
4. The CI job `guard` (below) fails any change under `phase-6` that touches a prototype path.
5. **Migration and retirement are manual and user-gated.** No agent runs them. They are listed
   in "Manual: migrate and retire the prototype" at the end. Deleting the root prototype files
   is a separate commit made after the person says so. It is not part of phase 6.

## Key decisions

| # | Decision | Where |
| --- | --- | --- |
| 1 | **New folder, new user data.** The app lives in `app/` with its own package (`name: switchyard-desktop`, `productName: Switchyard`). It sets `userData` explicitly to `<appData>/switchyard-desktop` **before** `ready`, because Electron would otherwise derive `Switchyard`, which on a case-insensitive macOS volume is the prototype's folder. At start it refuses any user-data folder whose basename equals `switchyard` in any case. This changes paths.md 2, which said phase 6 keeps the prototype's folder: that is not possible while the prototype runs, because Chromium's singleton lock is held per folder. | Contract C1, paths.md |
| 2 | **Usage goes to the hub through `sy`, not by HTTP from the app.** Each read becomes `web_usage` records (record.md 4.3) that are piped to `sy outbox append`, followed by a debounced `sy flush`. The machine's own token uploads them (machine id = `sy machine show --json`). So **the ingest API does not change**, records survive the hub being offline, and there is one outbox implementation (outbox.md 3). | C5 |
| 3 | **Two devices per computer, by design.** `sy` keeps its machine token (write). The app gets a **desktop** token (`sy_d_`, write + read) only to read: `/v1/overview`, `/v1/accounts`, `/v1/sessions`, `/v1/alerts` and `/v1/stream`. It never uses that token to ingest. The token is stored with Electron `safeStorage` and never touches disk in plain text, except on Linux's `basic_text` backend, where it is written with mode 0600 and Settings shows a warning. | C6 |
| 4 | **The hub board is shown, not embedded.** The board sends `frame-ancestors 'none'`, so it cannot sit in an iframe. It runs in its own `WebContentsView` in partition `persist:sy-hub` at the hub's URL. The app signs that partition in with `POST /v1/session/login` (desktop token → a read-only `sy_session` cookie), and an owner sign-in upgrades it. Home, Sessions, Accounts, Machines, Alerts and the hub's Settings are the board's own screens, so **the numbers match the board by construction**. | C7 |
| 5 | **Owner sign-in comes from `sy`, not from a password.** "Sign in as owner" runs `sy desktop owner-link --json`, which goes through the local hub, or the phase 5 admin channel (`machines.hub_admin`, e.g. `ssh oci sy`). It loads the one-time link in the hub view. Password and passkey sign-in (pairing.md 4, deferred "to phase 6") are deferred again: a non-goal. | C8 |
| 6 | **New `sy desktop` command group** (Go). It gives the app every hub-side action it needs as JSON: `info`, `token`, `owner-link` and `hub status|start|stop`. The app runs no other hub command and holds no SSH logic. | C4 |
| 7 | **The renderer has no network and no Node.** The shell is served from `app://shell/` with a strict CSP (`connect-src 'none'`). Every action is an allow-listed IPC call, checked for its sender and its arguments. claude.ai tabs and the hub view get **no preload at all**. | C2, C3 |
| 8 | **Reading follows decision 1 exactly.** It runs every 5 minutes (±15 s jitter, staggered 20 s per tab), and also when the tab opens. A plain warning is accepted once per tab and is versioned. There is an off switch per tab, and turning it off cancels the timers and drops any read still in flight. Errors back off from 5 to 60 minutes. A 401, 403 or 429 stops reading for that tab until the person presses **Resume**. | C5 |
| 9 | **Notifications come from hub alerts only.** An `alert` stream event with `change: fired` → `GET /v1/alerts/{id}` + `GET /v1/sessions/{id}` → OS notification. The hub's rules and quiet hours decide. The app has its own on/off switch, and it fires no notification of its own about limits. | C9 |
| 10 | **No runtime npm dependencies.** Dev dependencies are pinned exactly (no `^` or `~`): `electron`, `electron-builder`, `@electron/fuses`, `playwright-core`. Unit tests use `node --test`, so neither vitest nor a test framework is added. Main and shared code is ES modules; the preload is one self-contained CommonJS file, because sandboxed preloads cannot `require` relative files. | Wave 0 |
| 11 | **Packaging without publishing.** electron-builder: AppImage, deb and rpm; dmg; nsis. `publish: null` with `--publish never`, `mac.identity: null`, no notarizing, no Windows signing, no `electron-updater`. Fuses are flipped in `afterPack`. Signing and publishing are manual steps for "Before going public". | WP-F |
| 12 | **Schema v5 (small).** `seat.look_src` records who set a seat's label and colour (`ui`, `slot` or `import`), so a label set in the app wins over `slot_info` (record.md 4.7 already promises this). One new owner operation, `PATCH /v1/accounts/{seat}`, plus `stopped_reason` added to `Seat.places[]`. | C10 |

### CI job design (`.github/workflows/app.yml`)

Actions are pinned by full commit SHA, with the tag in a comment, as `ci.yml` does. WP-I
re-checks each SHA with `git ls-remote` on the day it writes the file. The SHAs below were
checked on 2026-10-13.

```yaml
name: app
on:
  workflow_dispatch:
  pull_request:
  push:
    branches: [main, phase-6]
    paths: ["app/**", "cmd/sy/**", "internal/**", "testdata/usage/**", ".github/workflows/app.yml"]
permissions:
  contents: read
concurrency:
  group: app-${{ github.ref }}
  cancel-in-progress: true
jobs:
  guard:            # the prototype must not change on this branch
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@fbc6f3992d24b796d5a048ff273f7fcc4a7b6c09 # v5.1.0
        with: {fetch-depth: 0, persist-credentials: false}
      - run: app/scripts/check-prototype-untouched.sh "${{ github.event.pull_request.base.sha || 'origin/main' }}"
  unit:
    strategy: {fail-fast: false, matrix: {os: [ubuntu-latest, macos-latest, windows-latest]}}
    runs-on: ${{ matrix.os }}
    defaults: {run: {working-directory: app, shell: bash}}
    env: {ELECTRON_SKIP_BINARY_DOWNLOAD: "1"}
    steps:
      - uses: actions/checkout@fbc6f3992d24b796d5a048ff273f7fcc4a7b6c09 # v5.1.0
        with: {persist-credentials: false}
      - uses: actions/setup-node@249970729cb0ef3589644e2896645e5dc5ba9c38 # v6.5.0
        with: {node-version: "22.x", cache: npm, cache-dependency-path: app/package-lock.json}
      - run: npm ci --ignore-scripts
      - run: npm run lint
      - run: npm test
  smoke:
    runs-on: ubuntu-latest
    needs: unit
    steps:
      - uses: actions/checkout@fbc6f3992d24b796d5a048ff273f7fcc4a7b6c09 # v5.1.0
        with: {persist-credentials: false}
      - uses: actions/setup-go@924ae3a1cded613372ab5595356fb5720e22ba16 # v6.5.0
        with: {go-version: "1.27.x", cache: true}
      - uses: actions/setup-node@249970729cb0ef3589644e2896645e5dc5ba9c38 # v6.5.0
        with: {node-version: "22.x", cache: npm, cache-dependency-path: app/package-lock.json}
      - run: CGO_ENABLED=0 go build -o "$RUNNER_TEMP/bin/sy" ./cmd/sy

        env: {SY_BIN: "${{ runner.temp }}/bin/sy", SY_SMOKE_OUT: "${{ runner.temp }}/smoke"}
      - if: failure()

  package:
    needs: smoke
    strategy: {fail-fast: false, matrix: {os: [ubuntu-latest, macos-latest, windows-latest]}}
    runs-on: ${{ matrix.os }}
    continue-on-error: ${{ matrix.os != 'ubuntu-latest' }}
    defaults: {run: {shell: bash}}
    env: {CSC_IDENTITY_AUTO_DISCOVERY: "false"}     # never sign
    steps:
      - uses: actions/checkout@fbc6f3992d24b796d5a048ff273f7fcc4a7b6c09 # v5.1.0
        with: {persist-credentials: false}
      - uses: actions/setup-go@924ae3a1cded613372ab5595356fb5720e22ba16 # v6.5.0
        with: {go-version: "1.27.x", cache: true}
      - uses: actions/setup-node@249970729cb0ef3589644e2896645e5dc5ba9c38 # v6.5.0

      - run: cd app && npm ci && node scripts/fetch-sy.mjs auto auto && npm run dist -- --publish never
      - if: runner.os == 'Linux'
        run: sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0 && xvfb-run -a node --test app/test/e2e/*.test.mjs
      - uses: actions/upload-artifact@330a01c490aca151604b8cf639adc76d48f6c5d4 # v5.0.0
```

for trying a build. `check-prototype-untouched.sh` lists `git diff --name-only <base>...HEAD`
and fails on any of: `main.js`, `preload.js`, `core/`, `server/`, `shell/`, `web/`, `bin/`,
`assets/`, root `package.json` / `package-lock.json`, `test/e2e.js`, `test/server.js`,
`test/preview.js`, `test/web-preview.js`, `Dockerfile`, `docker-compose.yml`. It skips itself
when the commit message carries `[prototype-retire]`, which is reserved for the person's
manual retirement commit.

1. Quit the prototype (tray → Quit; check that no `electron .` process is left).
2. In the new app: Settings → Import from the prototype → read the dry run → Import. Or run
   `Switchyard --import-prototype --dry-run`, then without `--dry-run`.
3. Check every imported tab is signed in and accept the warning on each. Leave the prototype's
   folder in place for at least two weeks as a fallback.
4. Turn on run at login in the new app. Remove the prototype's autostart entry by hand
   (`~/.config/autostart/switchyard.desktop`, or its login item).
5. Uninstall the prototype's hook script from your folders only when `sy hook` is set up
   (setup.md 10 leaves `~/.claude/switchyard-hook.sh` alone).
6. Later, and only when you say so: one commit marked `[prototype-retire]` that removes the
   root prototype files, updates `ARCHITECTURE.md` and README, and deletes the prototype's data
   folder by hand. This is not part of phase 6.

## Open risks

1. **Terms.** Background reading of an internal endpoint is the riskiest piece (decision 1).
   The warning, the off switch, the stop on 401/403/429 and the 5-minute floor reduce it. Before a
   public release, ask Anthropic (decision 2).
2. **claude.ai changes.** The endpoints, `lastActiveOrg` or the login flow may change; the
   reader is checked for shape, and a failure backs off instead of hammering. Fixtures in
   `testdata/usage` need refreshing when the shape changes.
3. **Cloudflare.** A plain-Chrome UA and staggered loads worked in the prototype. A challenge
   that wants a click shows in the visible tab only.
4. **Isolated-world fetch.** It worked in the prototype, which still kept a main-world fallback.
   If the isolated world loses cookies in a future Electron, the fallback runs in the page's
   world, where the page could alter the numbers (not the cookies); results are shape-checked.
5. **Import copies Chromium internals.** Copying a partition folder between two Electron apps
   of different versions usually works, but is not guaranteed (LevelDB and cookie schema
   upgrades are one-way). The prototype's folder is kept untouched as the fallback, and the
   import is copy-only.
6. **Unencrypted sign-ins at rest.** Electron's default stores cookies unencrypted. This is as
   in the prototype; turning the fuse on is a later, separate migration.
7. **Linux keyring.** Without a secret service, `safeStorage` uses `basic_text`; the token is
   then protected by mode 0600 only (the same as `sy`'s own token).
8. **Tray on GNOME** needs the AppIndicator extension; without it, closing quits unless
   "keep running" is set.
9. **CI sandbox.** The smoke depends on the runner allowing user namespaces (the sysctl step);
   if GitHub changes the image, the job fails loudly rather than falling back to
   `--no-sandbox`.
10. **Unsigned builds.** macOS Gatekeeper and Windows SmartScreen warn on the CI artifacts;
    fine for personal use, and signing is a manual step before going public.
11. **Phase 5 overlap.** WP-H touches `read_usage.go` and ingest, which phase 5 WP-C owned; if
    phase 5's wave 2 is still open, coordinate with its owner.
