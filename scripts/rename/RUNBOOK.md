# Rename runbook: Switchyard becomes Watchyard, `sy` becomes `wy`

<!-- rename:keep-begin: this file names the project before and after the rename on purpose. -->

The day-of procedure for the rename that `docs/spec/rename.md` describes. The version stays
**1.0.0**: the releases `v1.0.0` and `phone-v1.0.0` are deleted and published again under the
new name. For the maintainer; every step that touches GitHub, a machine, the hub or the phone
is run by you.

Total: about 3 hours, most of it waiting for CI and the release workflow.

| Step | What | Time |
| --- | --- | --- |
| 0 | Back up the old releases and each machine's binary | 15 min |
| 1 | Review the rename commit (or make it again with the tool) | 30 min |
| 2 | Merge to `dev`, then `main`; CI green | 30-45 min |
| 3 | Rename the GitHub repository; description, topics, Pages, social card | 15 min |
| 4 | Delete `v1.0.0`, tag `v1.0.0` again, wait for `release.yml` | 30-45 min |
| 5 | Build, sign and publish `phone-v1.0.0` again | 20 min |
| 6 | Existing machines: install `wy`, run the post-update steps | 10 min per machine |
| 7 | Hub: the app mirror picks up the new APK | 5 min |
| 8 | Desktop app and phone app on your devices | 20 min |
| 9 | Clean-up | 10 min |

## 0. Back up (before anything changes)

```sh
mkdir -p ~/rename-backup && cd ~/rename-backup
gh release download v1.0.0       -R mraj602/switchyard -D v1.0.0
gh release download phone-v1.0.0 -R mraj602/switchyard -D phone-v1.0.0
git -C ~/projects/personal/switchyard rev-parse HEAD > last-switchyard-commit
```

On every machine (hub, laptop, worker), keep the old binary:
`cp ~/.local/bin/sy ~/.local/bin/sy.pre-rename`. With the hub in Docker, also
`docker compose exec hub sy hub backup` (and copy the backup off the machine). Nothing below
moves or deletes data folders, but a backup costs a minute.

## 1. The rename commit

The branch `rename-watchyard` holds two commits on top of `dev`:

1. *Prepare the rename*: `internal/brand`, the migrations, `scripts/rename/`, the spec
   (`docs/spec/rename.md`). Behaves exactly like today while the old and new names are equal.
2. *Rename*: the output of the tool plus regenerated test goldens and the social card.

To make commit 2 again on a newer `dev` (rebase commit 1 first, then from a clean tree):

```sh
python3 scripts/rename/rename.py --to-slug watchyard --to-name Watchyard --cli wy \
    --android-id new --reissue --list
go test ./internal/board/tui ./internal/setup/plan ./internal/setup/tui -update   # goldens
# social card (temporary Chrome profile, never your own):
T=$(mktemp -d); google-chrome --headless --disable-gpu --hide-scrollbars --user-data-dir="$T" \
  --window-size=1200,630 --screenshot=site/img/social-card.png scripts/demo/social-card.html; rm -rf "$T"
make check && make app-test && make phone-check && make e2e-setup
git add -A && git commit -s -m "Rename Switchyard to Watchyard and sy to wy"
```

Review: `git diff --stat -M HEAD~1`, then the leftovers, which must all be the kept names
listed in `docs/spec/rename.md` 2.12 and section 1:

```sh
git grep -n -i switchyard -- . ':!scripts/rename' ':!docs/spec/rename.md'
git grep -n -E '(^|[^A-Za-z0-9_.-])sy([^A-Za-z0-9_-]|$)|\bSY_' -- . ':!scripts/rename' ':!docs/spec/rename.md'
```

Not regenerated by the tool (pictures with the old name in them): `docs/media/demo.gif`,
`site/media/demo.mp4`, `site/media/demo-poster.jpg` (`scripts/demo/record.cjs` says how), the
desktop stills (`scripts/demo/desktop-shots.mjs`) and the widget previews
(`phone/scripts/gen-widget-previews.py`). These were made again for this rename.
`docs/media/terminal-board.png` and `site/media/terminal-board.png` were remade by hand:
`wy board` in a 100x28 pty against `cmd/webui-dev`, rendered with `scripts/demo/term-shot.cjs`.

**Android signing.** `docs/RELEASING.md` now shows `~/secrets/watchyard-release.jks` and the
alias `watchyard`. Do not rename the keystore's alias or make a new key: the hub pins the
certificate (`appmirror.ReleaseCertSHA256`) and the app checks it. Point
`WY_ANDROID_KEYSTORE` and `WY_ANDROID_KEY_ALIAS` at the existing file and alias (the old
`SY_ANDROID_*` variables are still read).

## 2. Merge and CI

Merge `rename-watchyard` into `dev`, then `dev` into `main`, through the normal flow (signed-off
commits). Wait for `ci`, `app`, `phone` and `dco` to pass on `main`. Do not start step 3 with
a red `main`: the tag in step 4 must be on a green `main` commit.

## 3. GitHub repository

```sh
gh repo rename watchyard -R mraj602/switchyard --yes
git -C ~/projects/personal/switchyard remote set-url origin git@github.com:mraj602/watchyard.git
gh repo edit mraj602/watchyard --homepage https://mraj602.github.io/watchyard \
  --description "One board for every Claude Code account and machine. Self-hosted."
gh repo edit mraj602/watchyard --add-topic watchyard --remove-topic switchyard   # if it had one
```

- GitHub redirects `github.com/mraj602/switchyard` (web, git, API, release downloads) to the
  new name. **GitHub Pages does not redirect**: `mraj602.github.io/switchyard` stops working.
  Re-run the `pages` workflow (`gh workflow run pages.yml -R mraj602/watchyard --ref main`) and
  check `https://mraj602.github.io/watchyard/`.
- Social preview: upload `site/img/social-card.png` in Settings, General, Social preview (no API).
- Never create a new repository named `switchyard` under the account: it would end the redirects.
- Local clones elsewhere (other machines): `git remote set-url origin ...` there too, and
  rename the folder if you like (`~/projects/personal/switchyard`; it is only a path).

## 4. Release `v1.0.0` again

```sh
gh release delete v1.0.0 -R mraj602/watchyard --cleanup-tag --yes
git -C ~/projects/personal/switchyard tag -d v1.0.0
git checkout main && git pull
git tag -s v1.0.0 -m "v1.0.0"
git push origin v1.0.0
gh run watch -R mraj602/watchyard     # release.yml: make check, six archives, desktop packages
```

If GitHub refuses the tag or the release (immutable releases or a tag protection rule on the
account), stop here: the alternative is 1.0.1 (`--version 1.0.1` on the tool instead of
`--reissue`), which `sy update` would then see as newer.

The release now has `wy_1.0.0_<os>_<arch>` archives and, for old installers and `sy update`,
`sy_1.0.0_<os>_<arch>` copies holding a binary named `sy`. Check:

```sh
curl -fsSL https://github.com/mraj602/watchyard/releases/latest/download/install.sh | sh -s -- --no-setup --bin-dir "$(mktemp -d)"
gh release download v1.0.0 -R mraj602/watchyard -p 'wy_1.0.0_linux_amd64.tar.gz' -D /tmp/wy-check
gh attestation verify /tmp/wy-check/wy_1.0.0_linux_amd64.tar.gz --repo mraj602/watchyard
```

## 5. Release `phone-v1.0.0` again (on your machine; the key never leaves it)

From a clean checkout of the new `v1.0.0` tag, as in `docs/RELEASING.md` section 4 (with your
existing keystore file and alias, see step 1):

```sh
WY_RELEASE_NOTES="Watchyard 1.0.0" make phone-apk-release
apksigner verify --print-certs phone/dist/watchyard-1.0.0.apk   # SHA-256 must be 0b715b03...6dd644eddd
(cd phone/dist && sha256sum -c SHA256SUMS)
gh release delete phone-v1.0.0 -R mraj602/watchyard --cleanup-tag --yes
gh release create phone-v1.0.0 phone/dist/watchyard-1.0.0.apk phone/dist/SHA256SUMS \
  phone/dist/manifest.json -R mraj602/watchyard --target "$(git rev-list -n1 v1.0.0)" \
  --title "Android 1.0.0" --notes-file <notes with the fingerprint>
```

The app id is new (`io.github.mraj602.watchyard`): it is a new app beside the old one.

## 6. Existing machines

`wy update` cannot do this one: the re-issued release has the same version, so both the old
`sy update` and `wy update` say "current". Install `wy` by hand on each machine, hub first,
then the laptop, then the worker:

```sh
curl -fsSL https://github.com/mraj602/watchyard/releases/latest/download/install.sh | sh -s -- --no-setup
# ~/.local/bin/wy installed; ~/.local/bin/sy is now a link to it
wy update --post-update 1.0.0
# the steps an update runs: command, plugin (watchyard@wy-local), timer, hub service,
# agent service, machine_info, doctor
wy setup          # shows a plan: hooks, status line and launchers now call wy; confirm
```

Windows (PowerShell), then the same two commands:

```powershell
& ([scriptblock]::Create((irm https://github.com/mraj602/watchyard/releases/latest/download/install.ps1))) -NoSetup
```

A machine without internet (the push path): copy `wy_1.0.0_<os>_<arch>.tar.gz` there, put the
`wy` from it at `~/.local/bin/wy`, `ln -sf wy ~/.local/bin/sy`, then the same two commands.

Hub in Docker:

```sh
docker compose -p switchyard down          # keeps the volume
docker volume create watchyard_hub-data
docker run --rm -v switchyard_hub-data:/from:ro -v watchyard_hub-data:/to alpine cp -a /from/. /to/
# then, in the new checkout's deploy/:
docker compose up -d && docker compose exec hub wy doctor
```

Hub as a **system** unit (`/etc/systemd/system/switchyard-hub.service`, binary in
`/usr/local/bin`, perhaps with your own `sy-backup.service`/`.timer`): `wy update` and
`wy setup` manage only user units, so move these by hand. `wy doctor` (and the post-update
summary) lists every system unit whose name starts with `switchyard-` or `sy-` until then.

```sh
sudo systemctl cat switchyard-hub.service sy-backup.service   # note ExecStart, User, Environment
curl -fsSL https://github.com/mraj602/watchyard/releases/latest/download/install.sh \
  | sudo sh -s -- --bin-dir /usr/local/bin --no-setup
# /usr/local/bin/wy installed; /usr/local/bin/sy is now a link to it, so the old units keep working
cd /etc/systemd/system
sudo sed 's#/usr/local/bin/sy\b#/usr/local/bin/wy#g; s/Switchyard/Watchyard/g' switchyard-hub.service | sudo tee watchyard-hub.service
sudo sed 's#/usr/local/bin/sy\b#/usr/local/bin/wy#g' sy-backup.service | sudo tee wy-backup.service
sudo sed 's/sy-backup/wy-backup/g' sy-backup.timer | sudo tee wy-backup.timer
# Keep User=, --db, the data folder and every Environment= line as they were: SY_* variables
# are still read (WY_* wins when both are set), so nothing has to be renamed in them.
sudo systemctl daemon-reload
sudo systemctl disable --now switchyard-hub.service sy-backup.timer
sudo systemctl enable --now watchyard-hub.service wy-backup.timer
systemctl status watchyard-hub.service && curl -fsS http://127.0.0.1:8787/health   # your --listen
```

Keep the old unit files until the clean-up (step 9); to go back, `disable --now` the new units
and `enable --now` the old ones. Use the port and address of your own `--listen`.

Check on each machine:

```sh
wy doctor
wy paths        # "... switchyard folder from before the rename" is expected and fine
systemctl --user list-units 'switchyard*' 'watchyard*'   # only watchyard-* (Linux)
launchctl list | grep -i yard                            # only com.watchyard.* (macOS: hub, agent, flush)
ls -l ~/.local/bin/sy                                    # a link to wy
```

and in a Claude Code session: `/plugin` lists `watchyard@wy-local` and `watchyard-pane@wy-local`,
no `switchyard@sy-local`. On the board, each machine shows version 1.0.0 and is live.

## 7. The hub's Android app mirror

The hub keeps the mirrored APK in `<data>/app/android/1.0.0/` (`<data>` from `wy paths` on the
hub: on Linux the old `~/.local/share/switchyard` stays in use; in Docker `/data/app/android` in
the volume). Once `phone-v1.0.0` carries an APK with another SHA-256, the next mirror pass
replaces that folder: at hub start and then daily. To make it immediate, restart the hub
(`systemctl --user restart watchyard-hub`, or `docker compose restart hub`) and look for
`app mirror: phone-v1.0.0 published (build 10000)` in its log. If it says nothing:

```sh
systemctl --user stop watchyard-hub
rm -rf "<data>/app/android"        # only the mirror; nothing else in <data>
systemctl --user start watchyard-hub
```

If you ever set `app.android_repo` to `mraj602/switchyard`, the GitHub API redirect still
works, but set it to `mraj602/watchyard` (or clear it).

## 8. Your devices

- **Desktop app.** Install the new package. Linux deb and rpm replace `switchyard-desktop`; an
  old AppImage is just deleted. macOS and Windows install a new app beside the old one:
  uninstall the old one. On first start the app moves its data folder
  (`switchyard-desktop` to `watchyard-desktop`). On macOS and Windows the system keychain entry
  may not carry over: if the hub view asks, pair it again; if a tab asks, sign in to claude.ai
  again.
- **Android.** Install the new APK (sideload; Obtainium: change the URL to
  `https://github.com/mraj602/watchyard`). Pair it with the hub (it is a new device), check one
  notification and the widgets, then on the board revoke the old app's device and uninstall the
  old app. The old app never offers this APK as an update (another package id).

## 9. Clean-up

- System units moved in step 6: `sudo rm /etc/systemd/system/{switchyard-hub.service,sy-backup.service,sy-backup.timer}`
  and `sudo systemctl daemon-reload`.
- After every machine runs `wy`: `rm ~/.local/bin/sy.pre-rename`. Keep the `sy` link until the
  next release; `wy setup` has already rewritten what called it.
- `~/rename-backup` can go once a week passes without trouble.
- Old attestations under `mraj602/switchyard` stay valid for the deleted release; nothing to do.

## Rollback

- **Before step 3** (nothing published): revert the merge on `dev`/`main`. Nothing else changed.
- **After step 3, before step 4**: `gh repo rename switchyard -R mraj602/watchyard` and revert
  the merge. The old releases still exist.
- **After step 4/5**: rename the repository back, delete the new `v1.0.0` / `phone-v1.0.0`,
  and publish the backed-up assets from step 0 again
  (`gh release create v1.0.0 ~/rename-backup/v1.0.0/* --target "$(cat ~/rename-backup/last-switchyard-commit)"`,
  same for `phone-v1.0.0`). Release notes must be written again.
- **A machine**: `wy setup --undo` first (reverses the `wy setup` run: hooks, launchers,
  plugin pointers), then stop and remove the new units
  (`systemctl --user disable --now watchyard-hub watchyard-agent watchyard-flush.timer`, and
  delete their files under `~/.config/systemd/user/`), `rm ~/.local/bin/sy`,
  `mv ~/.local/bin/sy.pre-rename ~/.local/bin/sy`, `rm ~/.local/bin/wy`, and run `sy setup`
  (it installs the old service, timer and plugin again). Folders were never moved, so all data
  is where the old binary looks. Not rehearsed: check `sy doctor` afterwards.
- **Docker hub**: `docker compose down`, then start the old checkout's compose file with
  `-p switchyard`; it still uses the untouched `switchyard_hub-data` volume.
- **Phone**: the old app keeps working until you uninstall it; revoke the new one on the board.
